Dokumentacja dewelopera

Ten plik opisuje projekt BmsManagerVer10 od strony technicznej: co od czego zalezy, jak plyna dane, po co istnieja klasy i funkcje, jak dziala UART, baza danych, Web GUI, desktop viewer i aplikacja Android. Dokument jest interaktywny: uzyj wyszukiwarki, filtra warstw i zwijanych sekcji.

Backend API

Klasa BmsApiServer przyjmuje dane, normalizuje je, zapisuje do MySQL i wystawia endpointy dla aplikacji.

UART TinyBMS

BmsUartSender odczytuje BMS po porcie COM albo generuje dane SIMULATED.

Web i Desktop

dashboard.html/js/css renderuje Web GUI, a DesktopWebGuiApp pokazuje je w oknie JavaFX.

Android

Aplikacja mobilna odpytuje API przez Wi-Fi i pokazuje podglad danych z bazy/serwera.

Dlaczego projekt jest podzielony na kilka czesci?

Taki podzial pozwala uruchomic backend i baze bez podlaczonego BMS, testowac przez symulator, a interfejsy traktowac jako osobne klienty API. Dzieki temu awaria Androida albo Desktop Viewera nie zatrzymuje zapisu danych z BMS.

Przeplyw danych szczegolowo

1. Odczyt UART albo symulator

BmsUartSender dziala jako proces w tle. Gdy port to SIMULATED, tworzy realistyczna telemetrie: napiecie pakietu jest suma cel, prad zwykle jest blisko 0 A, a SOC zmienia sie powoli. Gdy port to COMx, sender wysyla komendy TinyBMS i parsuje odpowiedzi.

2. Przyjecie danych przez backend

Endpoint /api/ingest przyjmuje tekst. Funkcja ingestLine rozpoznaje typ: BMS, EVENT albo HEARTBEAT. Dane BMS ida do parseBms, eventy do parseEvent, heartbeat aktualizuje status komunikacji.

3. Zapis do bazy

persistReading zapisuje rekord do bms_readings i cele do bms_cell_readings. persistEvent zapisuje eventy do bms_events. Status zrodel zapisywany jest w bms_ingest_sources.

4. Odczyt przez aplikacje

Web GUI i Android nie czytaja bazy bezposrednio. Korzystaja z endpointow API: /api/latest, /api/history, /api/events, /api/health. To upraszcza aplikacje klienckie i pozwala kontrolowac format danych w jednym miejscu.

Dlaczego jest CRC?

UART nie gwarantuje, ze bajty dotra bez bledu. Funkcje addCRC/addCrc, crc16 i hasValidCrc licza CRC16 Modbus. Backend/sender ignoruje albo odrzuca ramki, ktore nie maja poprawnego CRC, zeby nie pokazac fałszywych wartosci.

Debugowanie

Backend nie odpowiada 
curl.exe http://127.0.0.1:8090/api/health

Jesli nie dziala, zrob mocny restart procesow Java i uruchom run_server_stack.bat.

Port COM nie dziala 
[System.IO.Ports.SerialPort]::GetPortNames()

Sprawdz, czy wybrany port jest na liscie. Jesli nie masz BMS, wybierz SIMULATED.

Android nie laczy sie z komputerem

Telefon musi byc w tej samej sieci Wi-Fi. W aplikacji wpisz adres komputera, np. http://192.168.31.70:8090, nie 127.0.0.1.

MySQL/XAMPP nie startuje

Sprawdz log XAMPP. Przy bledach InnoDB najpierw rob kopie C:\xampp\mysql\data, dopiero potem naprawiaj pliki logow.
